# 海洋测绘学习与科研周报

面向山东科技大学青岛校区测绘工程（海洋测绘特色班）大一学生：每周读懂值得关注的海洋测绘进展，找到公开数据、方法和适合入门的小任务。

## 看本周周报

打开 `reports/weekly-YYYY-MM-DD.md`，日期是本周一。先看海洋科研/数据线索，再看技术与工程应用，最后选一个任务。一般测绘方法最多两条；不要求每周一定有论文或规划新文件。

- 默认统计**上周一 00:00 至本周一 00:00，北京时间，右端不含**。例如 2026-11-09 周报对应 11-02 至 11-09 零点。
- 延迟到周二、周三也生成同一所属周，重复触发先检查是否已完成。
- 摘要为正文关键句节选和自动翻译，附原标题、原文、发布日期依据、正文状态。任务卡是学习建议，不能代替实验结论。
- 只得到标题的条目保留在数据库待核实，不伪装成已读原文；融资、人物、科普活动、会议与体育消息不进入技术主栏。
- 同一事件优先官方/正文充分的原稿；媒体配额按实际发布域名计数，每家最多三条，不因条目少而放松配额。
- 往周已刊的相同原文链接排除；同产品后续新事件允许收录，不凭书名号内名称永久判重。

## 本地运行

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe src/geomatics_news.py run --week-of 2026-11-09 --limit 15
```

省略 `--week-of` 使用当前周。`run` 总会执行本地重生成；`collect` 只采集，`report` 只生成。默认抓正文并尝试翻译；调试可用 `--no-translate`、`--no-content` 或 `--rolling --since-days 8`。滚动窗口仅用于调试，不与正式自然周混用。

`--config`、`--db`、`--report-dir` 可指定测试副本。请保留旧结果与原数据库备份，避免把试验内容当生产结果。2026-11-09 改版前周报保存在 `reports/archive/`。

## 来源与覆盖边界

配置在 `config/sources.yaml`。直接来源包括央广、新华社、中新网、自然资源部、国家海洋信息中心、海洋院所、高校；加入山科大测绘学院官网及本校新闻网测绘/海洋学院栏目。国际直连包括 NOAA、GEBCO、Seabed 2030、EMODnet、Copernicus Marine、UKHO 官方 Atom 和行业媒体。

中国政府网使用其页面链接的公开 JSON 列表；Google News RSS 为可选发现补充，尽量由正常跳转、公开原文链接或已读媒体订阅索引解析原文，不使用私有 RPC、不绕过验证。GDELT 因限流保持关闭；没有据此推断它被永久封禁。今日头条没有已验证的稳定直连采集，不能把“配置中出现平台名”说成已经覆盖。

IHO、UNESCO/IOC 和 Ocean Decade 等长期观察入口及目前未打通的部分见 [规划与标准观察清单](docs/planning-baseline.md)。旧文件单独阅读，不冒充本周新发布。

HTML 源最多读取配置的列表页数与详情预算。先扫描 RSS 日期再按预算抓正文。日志和 health.json 记录原始链接、主题排除、时间窗、缺失日期、正文可用、预算未访问等计数；没有全网覆盖或召回率保证。

## 定时与重生成

`.github/workflows/weekly.yml` 在北京时间周一至周三 08:17、10:47、13:23 提供触发机会。周二/三用于补发同一所属周；GitHub 仍可能延迟或丢弃定时事件，不能保证早晨准点。

所有入口先执行 `scripts/report_due.py`：

- 本期已完成且代码/配置版本相同则跳过；内容版本变更重新判定。
- 核心来源失败最多尝试三次；补充来源失败不否定核心完成，最多再补采一次。
- 在 Actions → Weekly Geomatics News → Run workflow，勾选 **force** 才强制重新生成；`week_of` 留空使用本周，补发旧周填周一日期。
- 运行结束先提交报告和数据库、保存 Artifacts，再展示来源状态。核心来源失败会让任务红色告警，补充源失败为 warning；绿色不代表全网新闻都已收录。
- 同分支任务排队，开始时取最新分支；不修改本机系统设置。

可独立部署的 Cloudflare 触发器位于 [ops/cloudflare](ops/cloudflare/README.md)。代码已准备，但部署需要仓库拥有者在自己的账户登录并存放 GitHub 令牌；本仓库不含凭据。独立触发也不保证 GitHub 执行机准点启动。若需要失败邮件，在 GitHub 通知设置确认 Actions 失败通知已开启；项目没有擅自配置邮箱、短信或付费服务。

## 健康状态与数据

`reports/health.json` 区分核心完成、补充源降级、所属周期、代码/配置版本、尝试次数、各源过滤计数和正文可用性。正常且零条不能解释为该站本周没发布新闻。规则变更重新审查历史行的资格，保存排除原因，不通过删除原始行“清理成绩”。

自然资源部兜底仅用于 GitHub 临时 Linux runner：从公共 DoH 获取新公网地址，验证 TCP/TLS 主机名与证书后才使用。不会关闭 HTTPS 校验，也不修改你的 Windows hosts。网站 HTTP 访问限制仍可能无法解决，会如实报错。

## 维护与反馈

[维护说明](docs/maintenance.md)列出验收和仍需账户操作的部分。每周挑一条你认为最有价值的新闻，记录值得读、误收或漏收及原因，逐渐形成与你和导师方向匹配的真实样本。现有测试保证已覆盖案例不回退，不能换算为线上准确率。
