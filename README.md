# Geomatics News：测绘与海洋测绘新闻周报

这是一个面向测绘工程（海洋测绘方向）学生的新闻采集器：直接读取国内公开新闻列表和官方 RSS，以 GDELT 作为补充检索，抓取可访问的正文，按专业关键词评分、去重、翻译后保存到 SQLite，并生成 Markdown 周报。

周报还会专门筛选与你的长期学习目标有关的内容：

- 中国“十五五”、海洋强国、海洋经济、海洋科技与海洋生态等政策信号；
- 联合国海洋科学十年、IHO S-100/S-102、GEBCO、Seabed 2030、EMODnet、Digital Twin Ocean 等国际规划和标准；
- 无人船/AUV、多波束、声呐、水深激光雷达、遥感、多源融合、人工智能、数字孪生、国产装备和精度控制；
- 数据集、算法、实验、论文、专利、验证和误差等适合本科科研与保研准备的线索。

这些规则是透明的关键词规则，不会把新闻自动变成正式的政策解读；阅读时应打开原文核对规划文件、时间表和指标。

## 本地运行

```powershell
# 进入本项目根目录（即包含 requirements.txt 的目录）
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python src/geomatics_news.py run --since-days 8
```

报告位于 `reports/`，数据库位于 `data/news.db`。

调试采集而不抓正文：

```powershell
python src/geomatics_news.py collect --no-content
```

不调用翻译服务：

```powershell
python src/geomatics_news.py run --no-translate
```

默认会先尝试 Google 翻译接口，再回退到 MyMemory；翻译失败时保留原标题和原文摘要，不会让任务失败。原文链接始终保留。

## 增加新闻源

编辑 `config/sources.yaml`。默认启用的国内入口独立于 GDELT：

| 来源 | 采集方式 |
| --- | --- |
| 央广网科技、新华网科技 | 公开新闻列表及文章页 |
| 自然资源部测绘、海洋栏目 | 公开新闻列表及文章页 |
| 桂林理工大学桂工要闻、中国科学院科研进展 | 公开新闻列表及文章页 |
| 中国新闻网即时新闻 | 官方 RSS |
| 国家海洋信息中心 | 官方公开新闻列表及文章页 |
| NOAA 海岸测量办公室、GEBCO | 官方 RSS，直接读取海道测量、海底测绘和数据更新 |

这些来源是限量读取栏目当前公开列表，并非全站搜索；只有确认日期且满足专业评分的条目才入选，某周可能没有海洋测绘新闻。正文提取会排除导航栏，避免把网页菜单里的“测绘”“海图”算成文章主题。

GDELT 国内、国际检索均保留为备用，因持续限流默认关闭；可在配置中手动启用。ESA RSS 继续启用。原 NASA RSS 返回了非有效订阅内容，暂时关闭。今日头条、人民网、央视网仍只在备用 GDELT 域名检索中，并非已经打通的直接来源；今日头条的搜索及部分文章路径在其 robots.txt 中限制抓取，因此不直接爬取，也不保证间接收录。头条平台包含不同作者，不能仅凭平台名称获得官方来源加分。

新 HTML 源需要配置 `url`、`article_url_pattern`、`required_terms`，必要时指定发布日期的 `date_xpath`。仅访问同域文章，限制篇数并在文章请求间隔 1 秒；访问失败或验证页面会记录状态，不绕过验证。

周报只使用最近 8 天的发布日期，旧数据库也按发布日期筛选。国内页面从日期元数据或明确的“发布时间”读取日期，无法核实日期时跳过；不会用页脚年份或采集时间替代。GDELT 的时间是它的发现时间，不能保证等于原始发表时间。

临时 DNS/连接故障和 HTTP 502/503/504 会有限重试。GitHub 临时运行环境在自然资源部 DNS 失败时，会通过 HTTPS 向 AliDNS、Google、Cloudflare 依次查询新地址，并仅将有效公网 IPv4 地址写入本次临时运行环境的 hosts 文件；没有硬编码 IP，不影响你的电脑。文章仍直接访问自然资源部原站，并校验原域名的 HTTPS 证书。解析仍失败时明确记录，不把它当作正常零条。备用解析不保证解决跨境网络或网站访问限制，国家海洋信息中心等入口补充覆盖，但不等于自然资源部原站已恢复。

手动启用 GDELT 后，查询至少间隔 10 秒；遇到 HTTP 429 会进入冷却并跳过后续查询，不连续重试，也不通过代理绕过限流。NOAA、GEBCO 等官方直连采集不依赖 GDELT。RSS 先检查发布日期，再抓正文，避免无效下载历史文章。

每份周报按以下顺序分区：十五五与国际海洋规划信号、未来海洋测绘技术、科研与保研高价值线索、海洋测绘重点、测绘与前沿技术。每条新闻显示海洋测绘、规划、未来技术和科研价值四项分数，并给出方向标签和学习提示。

周报末尾的“新闻源采集状态”列出正常、部分失败或失败及近期条数。运行显示绿色表示流程完成，来源是否覆盖完整以该表为准；“正常且 0 条”表示没有筛到符合日期、关键词的条目，不能理解为该网站本周没有发布任何新闻。

## 自动运行

`.github/workflows/weekly.yml` 设置每周一北京时间 09:17 首次运行，11:47、15:23 检查补跑；避开整点高负载，但 GitHub 不保证准时触发。补跑先检查当天周报是否存在：已存在则跳过采集；未存在则生成。并发运行会排队，排到后重新读取最新分支。手动 `Run workflow` 始终重新采集，即使当天已有报告。

报告日期固定使用北京时间，和运行机器时区无关。它会把周报和数据库提交回仓库。2026-10-19 的原 09:00 定时运行实际于 13:29:56 才创建，属于延迟触发；仅凭运行记录不能进一步确认 GitHub 内部原因。[GitHub 官方说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)指出，高负载（尤其整点）可导致延迟或丢弃。

三个时段仍共用 GitHub 调度器，不能保证平台故障时必定补跑。如果必须在固定时间前收到周报，需要独立调度器；现阶段手动触发仍可作为补救。

测试新配置时，在 Actions 左侧选择 `Weekly Geomatics News`，点击 `Run workflow` 并选择 `main`。旧运行记录里的 `Re-run jobs` 会继续使用旧工作流，请创建一次新运行来使用工作流修复。

工作流会读取所选分支的最新文件，同一分支的运行会排队执行。上传前会同步远程提交，避免配置更新导致推送被拒绝；如果数据库同时被修改而发生冲突，会停止上传，保留双方数据。每次成功生成的周报和数据库也会在运行页面的 Artifacts 中备份 30 天。
