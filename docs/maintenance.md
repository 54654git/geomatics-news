# 维护、验收与尚需账户操作

## 本次可在项目内完成的修改

- 按上一完整自然周生成，周二/三可以补发；手动、原生定时、外部触发共用所属周与幂等判断，force 明确控制重生成。
- 核心来源最多三轮、补充来源最多一次补采；版本变化重新采集，代码和配置都纳入版本。
- 分类先区分科研/数据/标准/技术工程、商业融资、人物/活动；标题线索不进入技术主栏。
- 聚合尽量回到原文，明确日期依据、正文可用性；实际媒体域名配额、事件去重、同产品新进展允许收录。
- 保留原始记录和排除原因；规则变更重审资格，旧周报备份保留。
- 来源计数覆盖列表、详情、日期、主题、正文和预算；核心/补充故障分别呈现。
- 加入本校学院、官方政策 JSON 和 UKHO；未打通的官方来源在规划观察清单列明。
- 正文关键句优先于 RSS 截断摘要，翻译缓存随输入变化更新；专业术语作规则修正。科研卡片给基础、任务和交付物。
- DoH 返回地址先验证 TLS 可达性，有限回退；仅作用于临时 runner。

1. 主栏不出现本期已发现的桌游、NOAA 人物专访、Mach9 融资；《海山图志》同一发布不重复。

## 需要你自己操作的账户事项

| 事项 | 我已准备什么 | 你需要做什么 |
| --- | --- | --- |
| 独立 Cloudflare 定时 | ops/cloudflare 中 Worker、配置及部署步骤 | 在你自己的 Cloudflare 账户登录；为这个仓库创建最小权限 GitHub 令牌并作为 Secret 保存，然后部署。无需把令牌发给聊天助手 |
| 失败邮件 | 工作流末尾对核心失败给出失败状态、补充失败 warning | 在 GitHub 通知设置里确认 Actions 失败通知的邮箱与开关；本项目没有自行使用你的邮箱 |
| IHO/Ocean Decade 等受访问限制的入口 | 观察清单、可失败的来源状态机制；没有绕过验证 | 可提供正常公开的官方订阅或文章链接用于验证；当前不保证这些机构的全部动态自动覆盖 |
| 最终科研方向 | 每条新闻附可做的小任务和资源缺失说明 | 你和导师结合课程基础、真实数据、实验条件决定；不把设备宣传或新闻热度当论文质量 |

未来真正的周一早晨准点交付仍需真实定时验收。人工 force 运行成功只能验证代码、采集和提交链路，不能证明下一周的调度必然按时。

## 每周小检查

先看本期所属周、来源告警，再读 1 条海洋重点，完成一个小任务。保留原图、数据许可和独立验证依据；GEBCO 粗格网适合区域可视化，不能充当米级浅水反演精度真值。
